Developing your own Vitess module

This tutorial will guide you to create a custom Vitess module.
There are four important steps to consider when developing a module:

  • Write the module source code in C or C++ and include it in the SRC folder.
  • Include the module in the Makefile located in `SRC/Makefile` and compile the software to generate the binary.
  • Include the module to the Graphical User Interface (GUI).
After following these steps, the new binary should be located in the MODULES folder and the module should appear in the GUI. So you should be able to start using your code. In what follows, we explain each one of these steps in detail with an example.
After adding your module, you may want to make use of all the functionalities offered by Vitess, such as the live mode and the visualization. Moreover, you may want to create some documentation of what the module does and how, for your future-self and for other users. Therefore, we encourage you to consider and go through a few more optional steps to complete your coding effort and make it more usable from other users:
  • Add a YAML file describing your module.
  • Add the ability to visualise the module.
  • Add the help file relative to your new module.

1. Write your module

As example we provide template.c source file in the SRC directory.
These templates serve as en example on how to create your own module. You can make a copy of this template and work on that.
A first consideration, is that modules are defined by a module ID. These are listed in a typdef enum that is in defines.h.\
We have created a general module ID called MCN_USER, but can directly add a new module ID to the list. If you do so, it is also necessary to modify the CompID2Name function in convert.c to copy the name of the module given the ID (create a new line and follow the logic in this function).
Finally, you also need to modify the Name2CompID function in convert.c in the same way, so that it knows how to convert from name to module ID and viceversa.
In the following part of the template the general initialization is performed by means of the Init function, and a PrintModuleName function.
After this, you must write an OwnInit function (given in the template) that sets the input parameters of the module and their flags to be used in the command line interface.
After treating all neutrons, Cleanup has to be called for writing into the log file and adding a line to instrument.inf, which stores the position of each component in a global co-ordinate system, and a function SetGeometry written for the instrument visualization.
There are several functions that Vitess offers to interact with the software. Some important ones are:
  • ReadNeutrons, which reads neutrons from the input stream and return the number of neutrons read,
  • WriteNeutron, which writes neutron to the output buffer that will be sent to the next module.
You can find them mostly in init.c.
There are also some Neutron structures like InputNeutrons (stores the input neutron Buffer) or OutputNeutrons (stores the output neutron Buffer) which are used to access the input and output neutron phase space variables.
The Neutron structure type definition can be found in defines.h. It is strongly recommended to look at some other modules in the SRC folder to see how these functions work and are implemented.
Some simple modules maybe space.c or slit.c to start with.
Some function in general.c in init.c facilitate handling structures or files, e.g. CopyVector, InitRotMatrix, LinesInFile, InitNeutron.
There are some auxiliary functions also to convert between physical properties, like for example ENERGY_FROM_LAMBDA or LAMBDA_FROM_V. These functions can be found in general.c and may be useful for you specific module.

2. Include the module in the Makefile and compilation

To be able to compile the Vitess software with your newly generated module it is necessary to include it into the `Makefile` which is located in `SRC/Ḿakefile`: `ALL = ascii2bin \ ... \ writeout \ template`. If the generated component depends on code in other files, you have to declare it like this: `template: template.c dependency.c` Now, whenever running $make all the new module will be compiled together with the rest of the bundle and you will see the binary inside the folder. Afterwards, you can run $make install to move the binaries into the `MODULES` folder. You may also run $make clean to clean the current directory of the binaries created. Now you have your module included in the vitess package and you can already add it to a command line pipeline to start using it!

3. Include the module to the Graphical User Interface (GUI)

First you need to modify GUI/vitess.tcl.
This part is optional if you intend to use the module by means of the GUI (recommended).
GUI files are inside the GUI folder. It is necessary to modify the vitess.tcl file to include a module by means of including the following lines (follow the other modules as an example).
First, add the module to the list of available modules by modifying the AvailableSET function.
In the example, we added the template inside the external_command menu:
{external_command {external_command template} {external_command template}}

Then add (also inside vitess.tcl) the function that defines the module content in the GUI:
set templateESET {
{"Template Module Title" header}
{fname pareditablefile "input file example" {"Input file space label" "Give out some help comment." "" M} r "" 1}
{}
{Variable1 int "10000" {"Example input variable" "Another help comment." "" n}}
}

You may find these lines already in the vitess.tcl file and modify them accordingly to your module. The template can be replaced with the name of your module.
In this example, the GUI of the template would have an input file box with a button to search for (that is the pareditablefile definition), which would have a label "Input file space label" and if right clicked would give the help "Give out some help comment". Whatever is passed as an input would be stored in the flag `M`, and the default value would be 1. The second and empty container {} would generate a space, and the last container would set an input box for a variable called Variable1 of type integer with a default value of 10000. Following the first example, it would be stored in the flag `n`. Flag letters do not necessarily have any logic, but they must be the same flag as set in the OwnInit function since these will be used to generate the command line prompt.
If you intend to add more parameters, just add more containers {} into the set.
You can grab ideas on how to use these by looking at other modules.

4. Add the YAML file (Optional)

This if for the module compatibility, because a YAML file will be required from version 4.0 onwards. This file should be located in the `YAML` folder of the VITESS directory. For general guidelines on how to create the YAML file, visit YAML files description. The YAML files are simple to read and you can get the basic ingredients by reading the YAML files of other modules.

5. Add the ability to visualise the module.

  • The following code changes are necessary in defines.h:
    • Add to McCompID a line such as MCN_mymodule = mymoduleID,
    • Add a struct with a unique name such as VtMystruct,
    • Add VtMystruct and an integer variable defining the module multiplicity such as nstruct to the structure VtModGeom,
  • The following code changes are necessary in init.h:
    • Add a void function that will print out the module parameters in the proper format.
      The name should be something like DrawMystruct.
      The void should at least have the following variables: FILE* pGeomFile, const char* pDescr, VectorType vAbsCntr, VectorType vDir. You can add more variables depending on your requirements for visualisation.
  • The following code changes are necessary in init.c:
    • Describe the void function DrawMystruct that you defined in the init.h
    • Add a for cycle to the void function WriteGeomData as it is done for the other structures
  • The following code changes are necessary in sortiap.c:
    • Add the material type such as MYSTRUCTMAT.
    • Add the Gtype such as GT_Mystruct.
    • Edit GTMAX accordingly. If you add one more GType add one to the current value of GTMAX.
    • Add the relative case to parseX3dOptionFile().
    • Update the function defineMaterials () if necessary.
    • Update the function shapeString.
    • Change the value MAXARGS if necessary.
    • Add the relative case to parseGeomItem.
    • Taking into account that y and z directions are defined following a different convention in Vitess and x3d, check if a case needs to be added in the function vitessToX3Dcoordinates.
    • Add the relative case to the function geom2X3D.

6. Add the help file relative to your new module.

This is easily done by adding a new html file to the WWW directory.
